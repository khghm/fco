# پشتیبان‌گیری و بازیابی (Backup and Recovery)

> **وضعیت:** تأییدشده · **نسخه:** v1.1 · **تاریخ:** ۱۴۰۵/۰۹/۰۳
> **مبنا:** Q-11 (پشتیبان offsite) · `ADR-010` (نگهداشت سه‌لایه) · `FR-15-07` · `FM-I-01/02`
> **قاعده بنیادین:** **پشتیبانِ بازیابی‌نشده وجود ندارد.** یک نسخه پشتیبان فقط پس از یک Restore موفق و مستند، «پشتیبان» شمرده می‌شود.
> **RPO/RTO:** هیچ عددی از پیش ادعا نمی‌شود؛ پس از اولین تمرین واقعی اندازه‌گیری و همین‌جا ثبت می‌شود.
> **مالک رویه پشتیبان، Restore، DR و ثبت نتیجه Drill.**

---

## ۱. دارایی‌های نیازمند پشتیبان

| # | دارایی | چرا | روش |
|---|---|---|---|
| ۱ | PostgreSQL (کل دیتابیس) | منبع حقیقت مالی/انباری | پایه + WAL |
| ۲ | فایل‌های ذخیره‌شده (رسانه محصول، پیوست تیکت، فاکتور PDF) | قابل بازسازی نیست (یا پرهزینه) | همگام‌سازی/نسخه‌برداری |
| ۳ | پیکربندی استقرار (بدون مقدار سری) | بازسازی سریع سرور | فایل نسخه‌دار در مخزن/مخزن پیکربندی |
| ۴ | اسرار و کلیدها | بدون کلید، پشتیبان رمزگذاری‌شده بی‌فایده است | سرویس مخفی + نسخه رمزگذاری‌شده جدا |
| ۵ | اسکریپت‌ها و Migration | بخشی از کد است | مخزن Git |

**ممنوع:** پشتیبان بدون رمزنگاری در مقصد offsite · نگهداری کلید رمزنگاری در همان سرور/همان نسخه پشتیبان · پشتیبان روی همان دیسکی که DB روی آن است (تنها نسخه).

## ۲. لایه‌های پشتیبان

```
لایه ۱ — پایه روزانه (pg_dump سفارشی، فشرده، رمزگذاری‌شده)      نگهداشت: روزانه × N
لایه ۲ — آرشیو WAL پیوسته (بازیابی نقطه‌ای)                      نگهداشت: کوتاه‌مدت
لایه ۳ — نسخه هفتگی/ماهانه (نگهداشت بلندمدت مالی)               نگهداشت: طبق ADR-010
لایه ۴ — کپی offsite رمزگذاری‌شده (مقصد جدا، دسترسی جدا)          همه لایه‌ها
```
| لایه | منبع | مقصد | رمزنگاری |
|---|---|---|---|
| پایه روزانه | `pg_dump -Fc` | دیسک پشتیبان محلی + offsite | ✅ (کلید مستقل) |
| WAL | `archive_command` | محلی + offsite | ✅ |
| هفتگی/ماهانه | کپی پایه منتخب | offsite | ✅ |
| فایل‌ها | rsync/نسخه‌برداری افزایشی | offsite | ✅ |

**زمان‌بندی پیشنهادی (تثبیت پس از اندازه‌گیری):** پایه در ساعات کم‌بار؛ WAL پیوسته؛ بازبینی موفقیت هر اجرا با هشدار در صورت شکست.

## ۳. رویه پشتیبان روزانه

```bash
# نمونه — مسیرها/نام‌ها بر اساس پیکربندی استقرار
TS=$(date -u +%Y%m%dT%H%M%SZ)

# ۱) پایه
pg_dump -Fc --no-owner --no-privileges "$DATABASE_URL" -f "/backup/base/fco-$TS.dump"

# ۲) بررسی صحت فایل (بدون بازیابی کامل)
pg_restore --list "/backup/base/fco-$TS.dump" > /dev/null

# ۳) رمزگذاری و انتقال offsite (کلید از سرویس مخفی)
age -r "$BACKUP_PUBLIC_KEY" -o "/backup/enc/fco-$TS.dump.age" "/backup/base/fco-$TS.dump"
rsync -a --partial "/backup/enc/fco-$TS.dump.age" "$BACKUP_TARGET/"

# ۴) ثبت نتیجه در گزارش
```
| الزام | جزئیات |
|---|---|
| بررسی موفقیت | خروجی صفر **و** `pg_restore --list` موفق |
| ثبت | زمان شروع/پایان، حجم، مقصد، نتیجه |
| هشدار | شکست پشتیبان = هشدار فوری؛ دو شکست پیاپی = حادثه |
| چرخش | حذف نسخه‌های قدیمی طبق سیاست، فقط پس از تأیید نسخه جدید offsite |
| فایل‌ها | نسخه‌برداری افزایشی + بررسی نمونه سالم |

## ۴. رویه بازیابی (Restore)

### ۴.۱ بازیابی کامل روی محیط جدا (آزمون یا DR)
```bash
# ۱) محیط تمیز (هرگز روی Production فعال)
createdb fco_restore

# ۲) رمزگشایی
age -d -i "$BACKUP_PRIVATE_KEY" -o /tmp/fco.dump "/backup/enc/fco-<TS>.dump.age"

# ۳) بازیابی
pg_restore -d fco_restore --no-owner --clean --if-exists /tmp/fco.dump

# ۴) بررسی صحت
psql fco_restore -c "select count(*) from oms.orders;"
psql fco_restore -c "select sum(quantity_delta) from inv.stock_ledger;"
psql fco_restore -c "select count(*) from fin.journals j
  join (select journal_id, sum(debit_rial)-sum(credit_rial) d
        from fin.journal_lines group by 1 having sum(debit_rial)<>sum(credit_rial)) x
  on x.journal_id=j.id;"     -- باید صفر باشد
```
| بررسی اجباری پس از بازیابی | انتظار |
|---|---|
| تعداد سفارش/سند در بازه نمونه | مطابق منبع |
| تراز اسناد مالی | صفر ناتراز |
| جمع دفتر موجودی vs `stock_balance` | اختلاف صفر |
| ورود و مشاهده پنل با داده بازیابی‌شده | کار می‌کند |
| مسیر Outbox (بدون ارسال واقعی بیرونی) | Worker متصل نشود یا آداپتور خاموش باشد |

**قاعده طلایی:** در محیط بازیابی، **آداپتورهای بیرونی خاموش** هستند تا پیام/پرداخت واقعی ارسال نشود.

### ۴.۲ بازیابی نقطه‌ای (PITR) — حذف اشتباهی
```bash
# ۱) توقف نوشتن (flag/حالت نگهداشت)
# ۲) بازگرداندن پایه + WAL تا لحظه هدف در محیط جدا
# ۳) استخراج داده لازم (جدول/ردیف) و انتقال کنترل‌شده به Production با سند
```
**قاعده:** بازگردانی کامل Production فقط با تصمیم مالک + TECH و ثبت پرونده حادثه؛ برای حذف یک رکورد، مسیر ترجیحی «استخراج و بازگردانی هدفمند» است، نه Rollback کل سیستم.

### ۴.۳ بازیابی یک جدول/سند
1. بازیابی پایه در محیط جدا → 2. استخراج ردیف‌های هدف → 3. درج با سند/اصلاحیه در Production → 4. Audit + گزارش.

**ممنوع:** `UPDATE` دستی روی سند مالی برای «بازگرداندن»؛ مسیر = سند اصلاحی (`BRQ-32`).

## ۵. سیاست نگهداشت (هم‌راستا با ADR-010)

| نوع نسخه | نگهداشت پیشنهادی | دلیل |
|---|---|---|
| روزانه | کوتاه‌مدت | بازگردانی سریع خطای روزانه |
| هفتگی | میان‌مدت | خطای دیرکشف |
| ماهانه | بلندمدت | الزام مالی/حسابرسی |
| WAL | کوتاه‌مدت | PITR |

- مدت‌های قطعی **پس از تأیید LEG-EXT/ACC-EXT** در `sys.settings` نسخه‌دار ثبت می‌شوند (نه هارد‌کد).
- حذف نسخه پشتیبان باید پس از تأیید موفقیت نسخه جدید و با ثبت انجام شود.

## ۶. رمزنگاری و کلید

| مورد | قاعده |
|---|---|
| الگوریتم | رمزنگاری نامتقارن/ابزار استاندارد (مثلاً age) یا AES-256 با کلید مدیریت‌شده |
| کلید عمومی | روی سرور برای رمزگذاری |
| کلید خصوصی | **جدا از سرور**، دسترسی محدود، نسخه کاغذی/گاوصندوق یا سرویس مخفی |
| آزمون کلید | دوره‌ای؛ بازیابی با کلید اشتباه باید شکست بخورد |
| چرخش کلید | نسخه‌های قدیمی با کلید قدیم قابل بازیابی بمانند |

**ریسک کلیدی:** از‌دست‌رفتن کلید = از‌دست‌رفتن همه پشتیبان‌ها. حداقل دو نفر با دسترسی و رویه تحویل مستند.

## ۷. تمرین بازیابی (Drill)

| مرحله | شرح | شاهد |
|---|---|---|
| ۱ | انتخاب نسخه (تصادفی، نه آخرین) | شناسه نسخه |
| ۲ | بازیابی روی محیط جدا | لاگ کامل دستورها |
| ۳ | بررسی‌های §4.1 | خروجی کوئری‌ها |
| ۴ | اندازه‌گیری زمان | RTO واقعی |
| ۵ | ثبت در همین سند + `RISK_REGISTER` | تاریخ + نتیجه |
| ۶ | رفع نقص‌های کشف‌شده | تغییر + بازآزمون |

**دوره پیشنهادی:** ماهانه برای پایه؛ فصلی برای PITR. عدم اجرا = ریسک باز (`R-09`).

## ۸. سناریوهای فاجعه (DR)

| سناریو | اثر | مسیر بازیابی | مالک |
|---|---|---|---|
| از‌دست‌رفتن سرور | توقف کامل | ساخت سرور جدید → نصب → بازیابی پایه + WAL → Smoke | TECH |
| خرابی دیسک DB | توقف DB | جایگزینی دیسک → بازیابی از آخرین پایه + WAL | TECH |
| حذف اشتباهی داده | داده ناقص/غلط | PITR در محیط جدا → استخراج هدفمند → سند اصلاحی | دامنه + FIN |
| فساد داده (باگ) | اسناد نادرست | شناسایی بازه → بازسازی از دفتر/رویداد → سند اصلاحی | دامنه |
| از‌دست‌رفتن کلید | پشتیبان غیرقابل‌استفاده | کلید پشتیبان در محل دوم | OWNER |
| ransomware/نفوذ | داده رمزگذاری/دزدی | قطع دسترسی، حفظ شواهد، بازیابی از نسخه سالم، چرخش اسرار | TECH |
| حذف نسخه‌های پشتیبان | کاهش پنجره بازیابی | هشدار + توقف حذف + بازسازی نسخه‌ها | TECH |

**قاعده:** هر سناریو یک Runbook با دستور واقعی دارد، نه توصیه کلی.

## ۹. مسئولیت‌ها

| نقش | مسئولیت |
|---|---|
| TECH | اجرای پشتیبان، پایش، Drill، بازیابی |
| OWNER | دسترسی به کلید، تصمیم بازگردانی Production |
| FIN | تأیید صحت داده مالی پس از بازیابی |
| دامنه (WH/SALES) | تأیید صحت داده عملیاتی پس از بازیابی |

## ۱۱. شکاف‌های باز

1. **هنوز هیچ Drill اجرا نشده؛ RPO/RTO نامعلوم است.**
2. مقصد offsite و مشخصات آن تصمیم نشده (Q-11 باز).
3. مدت نگهداشت قطعی منتظر تأیید حقوقی/مالی (ADR-010).
4. روش نگهداری کلید خصوصی (گاوصندوق/سرویس مخفی) تثبیت نشده.
5. پشتیبان فایل‌های رسانه تا فعال‌سازی Storage (BR-2) موضوعیت ندارد.
