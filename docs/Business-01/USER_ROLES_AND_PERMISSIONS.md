> **قاعده بنیادین:** کد به **نام نقش** وابسته نیست؛ فقط به **مجوز** وابسته است. نقش = بسته‌ای از مجوزها در `sys_role_permission`.

## ۱. مدل دسترسی در یک نگاه

```
کاربر ──(چند نقش)──> نقش ──(بسیاری)──> مجوز  <domain>.<action>
                                          │
                                          ├── محدود به منبع (scope): همه / تیم / خودم
                                          ├── محدود به فیلد (field-level)
                                          └── مشروط به آستانه (threshold) → تأیید دوم
```

سه لایه بررسی، همه در سرور:
1. **احراز هویت:** نشست معتبر (`ADR-007`) + MFA برای نقش حساس.
2. **مجوز عملیات:** کاربر مجوز `<domain>.<action>` را دارد؟
3. **مالکیت/دامنه منبع:** رکورد متعلق به دامنه مجاز اوست؟ (ضد IDOR — `FM-S-01`)

> نبود لایه ۳ = نقص امنیتی حتی با وجود لایه ۲. هر endpoint که شناسه منبع می‌گیرد باید مالکیت را بررسی کند.

**قواعد نقش:**
- هیچ نقشی «ابرکاربر» نیست؛ حتی `R-SYS` در عملیات مالی **نمی‌تواند** سند ثبت/تأیید کند.
- ترکیب نقش‌ها مجاز است ولی محدودیت SoD (بخش ۵) اولویت دارد.
- نقش موقت با تاریخ انقضا مجاز است (`valid_until`)، با Audit.
- نقش‌های `R-CEO`/`R-FIN`/`R-SYS` حداقل دو نفر (جایگزین) دارند تا گلوگاه تأیید ایجاد نشود (`FR-1-10`).

## ۵. تفکیک وظایف (SoD)

| قاعده | توضیح | نقض = |
|---|---|---|
| SoD-1 | ایجادکننده پرداخت ≠ تأییدکننده پرداخت | FM-F-01 |
| SoD-2 | درخواست‌کننده استرداد ≠ تأییدکننده استرداد | FM-F-03 |
| SoD-3 | ثبت شمارش ≠ تأیید مغایرت | FM-O-05 |
| SoD-4 | تخصیص نقش ≠ تأییدکننده خود (R-SYS نمی‌تواند به خودش نقش بدهد) | FM-H-06 |
| SoD-5 | بستن دوره ≠ ثبت سند همان دوره پس از بستن | FM-H-05 |
| SoD-6 | تغییر نرخ مالیات ≠ تنها تأییدکننده آن | R-05 |
| SoD-7 | `R-SYS` نمی‌تواند سند مالی ثبت یا تأیید کند | اصل ۱ |

**پیاده‌سازی:** بررسی در Application Layer + قید در `DB` (مثلاً `created_by <> approved_by`) تا حتی با دور زدن UI هم نقض ممکن نباشد.

## ۶. آستانه‌های تأیید (پیکربندی‌شده، نسخه‌دار)

| عملیات | آستانه | تأیید مورد نیاز |
|---|---|---|
| تعدیل موجودی | بیش از مقدار/ارزش تعیین‌شده در تنظیمات | R-WH ثبت + تأیید دوم (R-WH دیگر / R-FIN) |
| پرداخت به تأمین‌کننده | هر مبلغ بالای سقف روزانه | R-ACC + R-FIN |
| استرداد | همه موارد | R-FIN (مستقل) |
| تخفیف بالای سقف | درصد/مبلغ | R-SALES + R-FIN |
| لغو سفارش ارسال‌شده | همه | R-SALES + R-FIN |
| تغییر نقش | همه | R-SYS + R-CEO |

> **هیچ آستانه‌ای در کد هارد‌کد نمی‌شود** (`FR-15-04`). آستانه در `sys_setting` با `effective_from` و نسخه.

## ۷. نشست، MFA و چرخه عمر دسترسی

| موضوع | قاعده |
|---|---|
| نشست | کوکی HttpOnly/Secure/SameSite=Lax؛ چرخش شناسه پس از ورود؛ انقضای بی‌فعالیتی؛ ابطال مرکزی |
| MFA | الزامی برای R-CEO/R-FIN/R-ACC/R-SYS/R-SALES/R-WH/R-SUP/R-MKT؛ TOTP |
| OTP مشتری | محدودیت نرخ، انقضا، ضد Brute Force (`FR-1-01`، `FM-S-07`) |
| بازیابی رمز | بدون افشای وجود حساب (`FR-1-08`) |
| غیرفعال‌سازی کارمند | ابطال همه نشست‌ها در همان لحظه؛ محتوای ایجادشده حفظ می‌شود (اتریبیوشن تغییر نمی‌کند) |
| بازبینی دسترسی | گزارش diff مجوزها در هر تغییر + بازبینی دوره‌ای (`FM-H-06`، `FM-Z-08`) |
| ورود ناموفق | قفل تدریجی + ثبت در Audit + هشدار |

| مورد | قاعده |
