# Business Operations Blueprint — از تأمین تا تسویه و مرجوعی

> **وضعیت:** تأییدشده (G0) · **نسخه:** v1.0 · **تاریخ:** ۱۴۰۵/۰۹/۰۲
> **خروجی ۳ از ۱۰** — هر گام سند مرجع، گذار وضعیت، اثر مالی، اثر موجودی و نقطه شکست دارد.
> **مالک ایستگاه‌های `S1..S12` و اثر مالی/انباری هر ایستگاه.** گام‌های اجرایی در `BUSINESS_WORKFLOWS.md`.

## ۰. چهار جریان موازی روی یک واقعیت

```
کالا      : تأمین ─> انبار ─> برداشت ─> بسته ─> مرسوله ─> مشتری ─> مرجوعی ─> انبار
پول       : پرداخت خرید ─> دریافت فروش ─> تسویه درگاه ─> هزینه حمل ─> استرداد ─> خزانه
اطلاعات   : کاتالوگ ─> قیمت ─> سفارش(Snapshot) ─> وضعیت ─> گزارش ─> تصمیم
تعهد      : رزرو ─> تخصیص ─> تعهد ارسال(SLA) ─> AP/AR ─> تعهد مرجوعی
```

**قاعده طلایی:** هر تغییر در جریان کالا یا پول باید یک **سند** با شناسه، عامل، زمان، دلیل و مرجع تولید کند. هیچ عددی «ویرایش» نمی‌شود؛ فقط سند جدید صادر می‌شود.

## ۲. جزئیات ایستگاه‌ها

### S1 — برنامه‌ریزی و بودجه
- ورودی: فروش تاریخی فصل مشابه، موجودی فعلی و در راه، بودجه نقدی، تقویم فصلی.
- خروجی: **برنامه فصل نسخه‌دار** + سقف بودجه + منحنی سایز.
- قاعده: خرید بیش از سقف بودجه نیازمند تأیید دومرحله‌ای؛ منحنی سایز ثبت شود (پایه سنجش عدم توازن).
- اثر مالی: هیچ (تعهد پیش‌بینی‌شده خارج از دفتر کل).
- نقطه شکست: پیش‌بینی خوش‌بینانه → موجودی راکد؛ پاسخ: مقایسه برنامه/واقعیت دوره‌ای + Sell-through.

### S2 — تأمین و خرید
- وضعیت‌های PO: `Draft → Approved → Sent → PartiallyReceived → Received → Invoiced → Closed` + `Cancelled`.
- قاعده: دریافت ناقص مجاز ولی PO بسته نمی‌شود؛ مغایرت سند جدا دارد؛ قیمت فاکتور بالاتر از PO نیازمند تأیید مالی.
- اثر مالی: بدهی در **دریافت** شناسایی می‌شود، نه در صدور PO.
- اثر موجودی: **هیچ** تا رسید انبار.
- نقطه شکست: تأخیر/نقص تأمین‌کننده → صف پیگیری، هشدار زمان تأمین، اثر بر تعهد فروش.

### S3 — ورود و جانمایی
- فعالیت: شمارش/اسکن، کنترل کیفیت، تفکیک سالم/معیوب، بارکد، جانمایی، رسید.
- خروجی: GRN + سند گردش مثبت + قرنطینه برای معیوب.
- قاعده: رسید فقط با PO معتبر؛ بارکد تکراری/ناشناخته بلاک؛ معیوب وارد قابل فروش نمی‌شود.
- اثر مالی: بهای تمام‌شده و لایه هزینه (ADR-009).
- نقطه شکست: اسکنر خراب → ثبت دستی با دلیل و تأیید سرپرست.

### S4 — آماده‌سازی عرضه
- محتوا، ویژگی، جدول اندازه، تصاویر هر رنگ، قیمت، دسته/برند، وضعیت عرضه.
- قاعده: بدون قیمت فعال یا موجودی قابل عرضه، محصول در فروشگاه دیده نمی‌شود (یا «ناموجود» طبق سیاست)؛ تغییر قیمت، سفارش قبلی را تغییر نمی‌دهد.
- نقطه شکست: قیمت اشتباه منتشر شود → اصلاح فوری + گزارش سفارش‌های اثرگرفته.

### S5 — تقاضا و تخفیف
- کمپین (مخاطب، محصول، بودجه، بازه)، کد تخفیف، لندینگ، کانال، زمان‌بندی.
- قاعده: ترکیب تخفیف قابل‌پیکربندی؛ سقف استفاده؛ هشدار سود منفی؛ توقف کمپین رزروها را خراب نکند.
- اثر مالی: هزینه کمپین جدا؛ تخفیف حساب مستقل.
- نقطه شکست: بدون بودجه سخت → زیان؛ پاسخ: بودجه + هشدار مصرف + Stop Rule.

### S6 — سبد و Checkout
- اعتبارسنجی نهایی سرور: موجودی، قیمت، تخفیف، مالیات، هزینه ارسال.
- اثر موجودی: **رزرو موقت** با انقضا (A-12) — جزو گردش، نه تعدیل.
- وضعیت پرداخت: `Initiated → Pending/Unknown → Succeeded/Failed/Cancelled/Expired`.
- قواعد: کلیک مکرر = یک سفارش؛ پرداخت موفق بدون بازگشت کاربر باید کشف شود.

### S7 — سفارش و تخصیص
- تعیین انبار منبع، تخصیص تنوع، Pick List، اولویت SLA.
- قاعده: تخصیص مجدد فقط با سند؛ کالای رزروشده به سفارش دیگر داده نمی‌شود.
- نقطه شکست: کمبود پس از پرداخت → جایگزینی تأییدشده یا لغو + استرداد کامل؛ مشتری بلاتکلیف نمی‌ماند.

### S8 — برداشت و بسته‌بندی
- اسکن هر قلم، کنترل تطابق SKU/رنگ/سایز/تعداد، وزن، لیبل.
- قاعده: بدون اسکن موفق بسته‌بندی نهایی نمی‌شود؛ خروج موجودی فقط با **سند ارسال**.
- نقطه شکست: دو سفارش مشابه روی یک میز، بارکد ناخوانا، کمبود یک قلم.

### S9 — ارسال و تحویل
- وضعیت‌ها: `Created → Labeled → HandedOver → InTransit → OutForDelivery → Delivered` + `Failed/Returned/Lost/Damaged`.
- اثر مالی: هزینه حمل تعهدی در تحویل به حمل؛ تسویه با تطبیق صورتحساب.
- نقطه شکست: Webhook قطع → Polling؛ مفقودی → پرونده خسارت + راهکار مشتری.

### S10 — تسویه و تطبیق
- تطبیق تراکنش‌به‌تراکنش، کارمزد (هزینه، نه کاهش فروش)، واریز بانک، سند دریافت.
- قاعده: مغایرت بدون دلیل و مالک بسته نمی‌شود.
- نقطه شکست: تراکنش موفق بدون سفارش یا برعکس → صف مغایرت با SLA.

### S11 — مرجوعی/تعویض/انصراف
- وضعیت RMA: `Requested → UnderReview → Approved/Rejected → InTransitBack → Received → Inspected → Resolved → Closed`.
- مسیرها: (الف) انصراف قبل از ارسال: لغو + آزادسازی رزرو + استرداد (ب) مرجوعی پس از تحویل: RMA + بازرسی (ج) تعویض + سفارش جایگزین + مابه‌التفاوت.
- اثر موجودی: فقط پس از بازرسی و بر اساس وضعیت.
- قاعده: یک RMA فقط یک استرداد (Idempotency).

### S12 — پایان دوره
تطبیق کامل → ارزش‌گذاری و COGS → انطباق سفارش/درآمد/مالیات → صورت‌های مالی → قفل دوره → گزارش تحلیلی.

## ۳. ماشین وضعیت سفارش

```
Draft ──> AwaitingPayment ──> Paid ──> Allocated ──> Picking ──> Packed ──> Shipped ──> Delivered ──> Closed
   │              │              │                    │            │
   │              ├─> PaymentUnknown (تطبیق بعدی)     │            └─> Returned
   │              └─> PaymentFailed ──> Cancelled     └─> Blocked(دلیل)
   └─> Abandoned
```

هر گذار: مجوز نقش + پیش‌شرط داده + رویداد + ثبت تاریخچه. گذار غیرمجاز از API رد می‌شود.

## ۴. مدل ثبت مالی (نگاشت قابل‌پیکربندی)

| رویداد | ثبت پیش‌فرض | یادداشت |
|---|---|---|
| PaymentSucceeded | بدهکار: درگاه/بانک · بستانکار: پیش‌دریافت | درآمد شناسایی نمی‌شود |
| Shipped/Delivered | بدهکار: پیش‌دریافت · بستانکار: درآمد + مالیات | زمان شناسایی قابل‌پیکربندی |
| COGS | بدهکار: بهای تمام‌شده · بستانکار: موجودی | بر پایه ADR-009 |
| Discount | حساب تخفیف (کاهش درآمد) | ردیف مستقل برای تحلیل |
| Refund | برگشت از فروش + برگشت مالیات | سند اصلاحی |
| GRN/PurchaseInvoice | موجودی / پرداختنی | پس از تطبیق سه‌طرفه |
| CarrierInvoice | هزینه حمل / پرداختنی | تطبیق با مرسوله‌ها |
| StockAdjustment | موجودی ↔ کسری/مازاد | تأیید دومرحله‌ای |

## ۵. رویدادهای دامنه

`OrderCreated` · `InventoryReserved/Released` · `PaymentSucceeded/Failed/Unknown` · `OrderAllocated/Packed` · `ShipmentCreated/Delivered/Lost` · `ReturnApproved/RefundCompleted` · `StockAdjusted` · `PurchaseOrderReceived`

هر رویداد: `eventId`, `occurredAt` (UTC), `correlationId`, `version`, Idempotency Key.

## ۹. نقاط تطبیق

| تطبیق | منبع A | منبع B | رفتار در مغایرت |
|---|---|---|---|
| سفارش ↔ پرداخت | سفارش | درگاه/بانک | صف مغایرت + بررسی انسانی |
| پرداخت ↔ تسویه درگاه | پرداخت‌ها | فایل تسویه | مغایرت کارمزد/تراکنش گمشده |

| خرید ↔ رسید ↔ فاکتور | PO | GRN | فاکتور | تأیید قبل از AP |
| موجودی ↔ ارزش | دفتر گردش | دفتر کل | تعدیل مستند |
| مرجوعی ↔ استرداد | RMA | سند پرداخت | جلوگیری از استرداد دوباره |

## ۱۱. شاخص‌های پایان‌به‌پایان

فروش (تبدیل، AOV، لغو، سهم کانال) · سود (حاشیه، سود منفی per-SKU) · موجودی (گردش، Sell-through، توازن سایز، راکد) · عملیات (زمان پرداخت→تحویل، خطای بسته‌بندی) · حمل (به‌موقع، تأخیر، مفقودی) · پس از فروش (نرخ مرجوعی به علت/SKU) · مالی (زمان تسویه، مغایرت باز، اسناد ناقص) · بازاریابی (ROAS، CAC، CLV، Cohort)
